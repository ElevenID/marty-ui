# Published ISO-2022 mappings and state behavior

Seven language-neutral artifacts qualify `iso2022_kr`, `iso2022_jp`,
`iso2022_jp_1`, `iso2022_jp_2`, `iso2022_jp_2004`, `iso2022_jp_3` and
`iso2022_jp_ext`. They are generated by `scripts/canvas_iso2022_codec_oracle.py`,
not by the Rust decoder. Two independent complete captures agreed for each
variant before native implementation.

Both captures used this published image with network disabled, read-only inputs
and root filesystem, dropped capabilities and no-new-privileges:

`ghcr.io/elevenid/marty-credentials-issuance@sha256:9f15b64bc0ec7a693339cada3142b2952a575d2b50ee89230aabe078d0026176`

The image contains CPython 3.12.13 and HTTPX 0.26.0. The corresponding official
[ISO-2022 source](https://github.com/python/cpython/blob/v3.12.13/Modules/cjkcodecs/_codecs_iso2022.c)
was inspected; raw SHA-256 is
`f495710505aa93c5610d8c38c543b057416e5508b9fb6337bbae6d2a4b85c707`.
The [incremental decoder](https://github.com/python/cpython/blob/v3.12.13/Modules/cjkcodecs/multibytecodec.c)
and [pending-buffer limit](https://github.com/python/cpython/blob/v3.12.13/Modules/cjkcodecs/multibytecodec.h)
explain behavior that differs from one-shot strict decoding. Mapping values,
variant flags and expected output hashes are measured from the image.

## Format

Schema `marty.canvas-iso2022-codec/v1` contains:

- `sets`: accepted non-ASCII designation marks, observed one/two-byte widths,
  compressed u32LE output indices and compressed UTF-8 JSON output arrays.
  Null output means unmappable. The first byte ranges from 32 through 127;
  two-byte tables cover every second byte from 0 through 255. Multi-character
  JIS mappings and supplementary scalars remain strings, not lossy scalar casts.
- `shift`, `g2`, `extension`: independently observed variant behavior switches.
- `prefixes`: 134 total canonical active-state witnesses across the variants.
  These cover active G0/G1/G2 choices, locking shift and escape pass-through.
  G1 does not affect decoding in NO_SHIFT variants; its designation syntax is
  still exercised by the escape mutations rather than duplicating states.
- `state_hashes`: 8,816,262 complete inputs per mode, comprising each witness,
  witness plus every byte, and witness plus every two-byte combination.
- `escape_seeds`, `tails`, `escape_hashes`: 6,386,038 complete inputs per mode,
  covering every seed prefix, every byte substitution at every seed position,
  recorded suffixes, and unterminated/repeated escape material at lengths around
  the scanner and pending-buffer boundaries. Rust replays the same generator.
- `g2_cases` and `g2_strict`: every third byte for accepted G2 single-shift
  designations, independently recorded in replacement and strict modes. Runtime
  mapping uses strict validity, never an assumption that U+FFFD means invalid.
- `cases`: 1,167 full HTTPX response examples, including aliases, control bytes,
  repeated text, mixed states and errors; all 23 recorded labels are exercised.

Hash framing reuses the multibyte contract: null records byte 0; strings record
byte 1, u32LE UTF-8 length and bytes. Exceptions record byte 2 followed by that
string framing around compact JSON with sorted `error` and `error_class` keys.
Fresh HTTPX decoders and Python strict decoding supply expectations, not replay
of the generated tables. Ordinary strict decode failures are null; distinct
internal codec exceptions retain their exact class and diagnostic.

## Native behavior and error boundaries

One Rust stateful owner serves all seven variants and both response/strict-label
callers. Shared bounded decompression validates data before lazy initialization.
The owner preserves designation acceptance, locking shift, newline handling,
pass-through escapes, mapping width, error consumption and variant extensions.
It does not substitute WHATWG behavior or route through runtime Python.

Two non-text outcomes are intentionally distinct:

- An unsupported G2 execution after an accepted designation raises
  `RuntimeError: internal codec error`, including through encoded charset labels.
- An incomplete escape longer than eight pending bytes raises
  `UnicodeError: pending buffer overflow` in HTTPX's incremental response decoder.
  One-shot strict label decoding instead follows the ordinary invalid-input path.

The old UTF-8 fallback failed the response regression. Deep hash replay then
identified the pending-buffer distinction; after repair all state/escape hashes
match. A diagnostic stream verified individual outputs and also exposed the
need to sort exception keys in hash framing. Temporary native diagnostic output
was removed; no permissive behavior or expected output was substituted.

## Consumer evidence

Two independent published-helper TLS captures grow 85 to 96 cases, preserving
all earlier observations. They include every variant, both error classes,
encoded-label failure and JSON-before-text bypass. Native TLS replays all 96.
The exact test-only path allowlist expands; production transport policy does not.

Two independent published application captures grow validation 31 to 37 and
status-provider 82 to 86 observations without changing prior entries. Native
managed-router replay and 17 real-HTTP validation cases check plain HTTP 500
versus ignored successful response text and structured JSON failure excerpts.
The shared PostgreSQL lifecycle fixture checks both codec error diagnostics,
later recovery, clearing both error fields, canonical status/counters, unrelated
metadata and publication ordering. This composes published provider observations
with native persistence, not a newly captured full published lifecycle trace.

The configured image gate regenerates and compares every complete artifact;
the CI runner requires the new persistence/recovery test to exist. The Rust
`capture_canvas_published_oracle` example reuses exact-owned disposable fixtures
for reference capture only; its output is not itself a passing qualification gate.
Remaining codec families and whole-worker/all-consumer adoption remain open.
