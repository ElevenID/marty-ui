## Representation and independent evidence

Schema `marty.canvas-euc-kr-codec/v1` records:

- `pairs_zlib_base64`: the same compressed little-endian u32 representation as
  [GB18030](canvas-gb18030-codec.md), with all 32,768 high-first-byte pairs and
  `0xffffffff` as the invalid sentinel.
- `base_scalar` and `components`: three 256-entry nullable offset arrays measured
  by varying each component byte in a valid eight-byte composition. The baseline
  decodes to U+AC00. Null means invalid; no Hangul mapping table is inferred from
  replacement characters.
- `short_hashes`: 65,792 independent single/two-byte inputs per decoding mode.
- `component_hashes`: baseline plus all 768 one-component variations per mode.
- `composition_hashes`: all 16,777,216 possible component-byte triples per mode,
  with the other five bytes fixed to the composition format. The capture also
  verifies the additive representation against the actual strict result for
  every combination. Exactly 11,172 compositions are valid.
- `mutation_hashes`: 98,304 complete inputs per mode. For each recorded base,
  every position receives every byte; each result is observed at lengths zero
  through eight and with ASCII, valid-composition and incomplete-prefix suffixes.
  Bases include first/last valid syllables and invalid structural/component bytes.
- `cases`: 98 full HTTPX response examples checked for all nine recorded labels,
  including repeated composition across the excerpt boundary and truncated input.

All expected hashes use fresh HTTPX replacement decoders and independent Python
strict decoding. Shared framing records byte 0 for strict failure, or byte 1,
u32LE UTF-8 byte length and UTF-8 bytes for text. Rust replays the exact inputs and
order; it does not compute expected hashes from its mapping representation.

## Native owner and consumer gates

`canvas_response_euc_kr.rs` supplies pair or eight-byte composition mapping to the
shared `decode_complete` owner in `canvas_response_multibyte.rs`. GB18030 reuses
the same pair validation and complete-input loop. Required length is determined
before validating sequence contents: an incomplete composition becomes one
replacement, while a complete invalid sequence consumes one byte and retries.
Strict label decoding uses the same implementation and returns failure instead.

The lazy initializer validates all pair scalars and component array lengths,
uniqueness, ranges and strides before use. No dependency or runtime Python shim
is introduced. Capture scripts share `CompleteInputOracle`; the existing GB18030
artifact must regenerate unchanged after that refactor.

The mandatory published-image gate compares the entire EUC-KR artifact and all
prior artifacts. Two independent published HTTP/response-helper TLS captures
agree, preserve all previous 84 observations, and add ordinary Korean text,
first/last composed syllables and invalid/truncated composition in one new case.
Only the exact test-fixture path allowlist expands; no production transport or
deployment policy changes. Remaining codec and whole-worker/all-consumer gates
are not qualified by this artifact.
