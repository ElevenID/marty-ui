# UTF-7 decoder and strict encoded labels

`canvas-utf7-codec.json` is generated by `scripts/canvas_utf7_codec_oracle.py`
using actual HTTPX replacement decoding and independent Python strict decoding
in the immutable published image:

`ghcr.io/elevenid/marty-credentials-issuance@sha256:9f15b64bc0ec7a693339cada3142b2952a575d2b50ee89230aabe078d0026176`

Two final captures agree. Expected data was frozen before native repairs; no
native output is used to generate expected results. The existing 195 label
observations remained identical when six additional codec-name boundary cases
were added. The initial native regression failed on a valid UTF-7 encoded label.

The official [CPython 3.12.13 decoder source](https://github.com/python/cpython/blob/v3.12.13/Objects/unicodeobject.c)
was inspected for state and error-consumption rules. Its normalized LF/UTF-8
source SHA-256 is `dd21107aaed90e06b85cae80de86f43f09e6c0bcb35b00037344cf96960bd431`.
The native implementation is independently exercised against published outputs,
not merely against a model translated from that source.

## Frozen coverage

Each mode covers 2,347,269 inputs:

| Group | Inputs | Coverage |
| --- | ---: | --- |
| short | 65,793 | Every zero-, one- and two-byte input |
| units | 524,288 | Every UTF-16 unit, four padding patterns, terminated/unterminated |
| pairs | 524,288 | Every unit before/after each high/low surrogate endpoint |
| supplementary | 1,048,576 | Every supplementary scalar represented by a surrogate pair |
| terminators | 7,168 | Every byte after the recorded shift/padding/pending-unit prefixes |
| grid | 177,156 | Lengths zero through five over eleven recorded byte classes |

The artifact also records 134 complete-input observations, with Python's final
replacement text verified at every two-part byte split of each example. Strict
errors retain byte start/end and reason. The existing 39 lossless helper/text
observations are replayed directly by the new native decoder tests.

Five verified aliases and encoded label examples produce 201 parameter/text/
excerpt observations. Cases distinguish successful non-scalar labels (rejected
by the final ASCII-label filter) from malformed strict decoding (raw-value
fallback), and include embedded NUL names and JSON/empty-body bypasses.

## Hash framing

Each corpus has replacement and strict SHA-256 digests. A successful text record
is byte 1, its codepoint count as u32LE, then each codepoint as u32LE, including
surrogates. A strict failure is byte 0, start/end/reason-byte-length as u32LE,
then ASCII reason bytes. This format does not require Rust str to represent
non-scalar Python text. Corpus ordering and input generation are explicit in
both the capture script and native regression.

## Native owner and adoption scope

`canvas_response_utf7.rs` shares one complete-input implementation between strict
and replacement modes. It writes directly into the lossless `PythonText` owner,
retains standalone surrogate codepoints where the published reader does, and
distinguishes malformed shift/padding/termination boundaries. No runtime Python,
generated mapping table or lossy scalar conversion is used.

Strict encoded charset labels now use this decoder. The label boundary keeps
successful non-scalar decoding distinct from decoder failure: the former cannot
be an ASCII charset name; the latter follows the published raw-label fallback.
Existing scalar codec owners are wrapped losslessly and their observations are
unchanged. Encoding-name validation is shared by response and strict-label paths;
embedded NUL preserves the published ValueError before alias normalization.

The published HTTP/provider/TLS corpora expand without changing any old result:
validation 41 to 47 (27 actual HTTP response cases), provider 90 to 97, TLS 99 to
104. Cases include decoded Latin-1 names, rejected non-scalar names, both NUL
locations, and successful/JSON bypasses. Two independent captures agree for each
expanded consumer corpus.

The shared persisted lifecycle scenario exercises a Latin-1 provider refusal,
a decoded-NUL failure, and successful JSON recovery. Existing assertions cover
exact persisted errors and clearing, canonical status, attempts, unrelated
metadata, secret use, publication ordering and late-save failure. Its required
27th configured image test is
`status_runtime_preserves_utf7_label_failures_and_recovery`.
The timeout image gate also regenerates and compares this entire codec artifact.

Response-body adoption is still open. `response_text` and downstream metadata/
error values have not yet been migrated to lossless text; the presence of this
decoder does not qualify those consumers or a native streaming interface.
The full credential-route result for non-scalar database-save failures remains
to be captured, as described in [consumer boundary evidence](canvas-text-boundaries.md).
Do not route the draft candidate or delete its Python owner on decoder tests alone.

## Reproduction

Run the capture script in the image above with itself and
`run_canvas_timeout_consumer_oracle.py` mounted as read-only siblings, no network,
read-only root, dropped capabilities and no-new-privileges. No credentials are
needed. The `observe(response_source)` API accepts independently verified frozen
source for the existing helper harness.

Native kernel and encoded-label tests are selected by `cargo test --lib utf7` in
the issuance package. The actual image comparisons require
`MARTY_CANVAS_PUBLISHED_SCHEMA_TEST=1`; an unset variable does not qualify them.
