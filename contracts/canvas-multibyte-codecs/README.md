# Published multibyte decoder machines

These language-neutral tables are generated by
`scripts/canvas_multibyte_codec_oracle.py --codec NAME`, not hand-maintained codec
implementations. Each was independently captured twice in the immutable issuance
image pinned by `canvas-worker-consumer-range-oracle.json`. The mandatory published
timeout-consumer gate regenerates and compares every complete artifact.

The 15 machines cover Big5, Big5-HKSCS, CP932, CP949, CP950, GB2312, GBK, Johab,
Shift-JIS, Shift-JIS-2004, Shift-JISX0213, EUC-JP, EUC-JIS-2004, EUC-JISX0213 and HZ.
They include 64 canonical/alias labels, 2,415 reachable states and 618,240 byte
transitions. Unsupported codec families are not silently added to this inventory.

The generator explores every reachable incremental replacement-decoder state,
retaining a witness byte prefix. For each state and next byte it independently
observes strict decoding too; the table distinguishes valid output from error
replacement, even when their text is identical. Finalization is recorded per state.

Schema `marty.canvas-multibyte-machine/v1`:

- `transitions_zlib_base64`: zlib-compressed little-endian u32 entries, in
  `[state * 256 + byte]` order. Bits 0..15 select an output string, bits 16..30
  select the next state, and bit 31 means strict decoding succeeds.
- `outputs_zlib_base64`: compressed UTF-8 JSON array of strings, including empty
  and multi-character outputs; `outputs_size` is its exact decompressed byte count.
- `finals`: the output index and strict-success flag when flushing each state.
- `prefixes`: hexadecimal witness bytes for each state in enumeration order.
- `text_sha256` / `strict_sha256`: independent complete-payload observations from
  fresh HTTPX TextDecoder and Python strict text decoding, respectively. Each
  state's witness prefix is followed by all 256 witness-plus-byte inputs. A failed
  strict decode records byte 0; success records byte 1, u32-LE UTF-8 byte length,
  then UTF-8 bytes. Expected hashes are not computed by replaying the table.
- `cases`: full HTTPX response text for 11 payloads; all registered aliases are
  checked against these independently. JSON excerpt behavior is qualified separately
  through the actual published response helper and TLS consumer corpus.

Rust uses one decoder for all machines and shares it with strict charset-label
decoding. Tables are lazily initialized, validated and decompressed with exact
length bounds using existing dependencies. Unknown/UTF-8 requests do not initialize
this registry. No Python is invoked by production.

Remaining families include GB18030, EUC-KR, ISO-2022, UTF-7 and other special or
escape codecs. The finite enumeration guard fails rather than truncating a machine;
larger or structurally different state spaces need deliberate qualification and
implementation. This inventory does not approve dropping those capabilities.
