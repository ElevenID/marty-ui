# Canvas continuation ordinals and UTF-7 boundaries

These fixtures preserve observed behavior from the immutable published image:

`ghcr.io/elevenid/marty-credentials-issuance@sha256:9f15b64bc0ec7a693339cada3142b2952a575d2b50ee89230aabe078d0026176`

Both capture scripts verify the installed adapter's normalized source SHA-256
(`24f5c0f22c075af3a11abbb48be52bcc6535e0d4fc31e446f7fb218bfe40d679`)
and use its exact extracted excerpt helper. Expected values are not produced by
Rust. Two independent read-only, network-disabled image captures agreed for
each fixture before the ordinal implementation.

## Continuation ordinals: native boundary implemented

`canvas-charset-ordinal-oracle.json` records 60 observations using
`scripts/canvas_charset_ordinal_oracle.py`. The image's decimal conversion limit
is 4,300 digits. Cases cover both sides of that boundary, leading zeroes,
ordinary and unrelated parameter groups, encoded continuations, and ignored
malformed parameter names/suffixes. Each header is exercised with text, valid
JSON and an empty body. Compact header specifications avoid repeating thousands
of digits in the artifact.

Rust checks the raw digit count only after recognizing a numeric continuation,
before trimming leading zeroes. Below the published limit, length/lexical
ordering still supports values larger than machine integers. Above it, the
shared typed error preserves the published `ValueError` class and message.
Ordinary charset precedence does not suppress errors from unrelated groups.
Empty-body and valid-JSON excerpt bypasses remain intact.

The new regression failed against the previous implementation before repair.
Both the existing 177 header observations and the new 60 observations share one
Rust assertion helper. The configured published-image suite regenerates and
compares both complete artifacts, also checking the refactored Python observer.
Two independent actual loopback TLS captures agree on 99 cases; all previous
96 observations are unchanged. The additions cover text failure and JSON/empty
success through the actual published client and excerpt helper.

Independent published application/provider captures add four validation and
four status-provider cases. Both pairs of captures agree; the previous 37
validation and 86 provider observations are unchanged. Validation exercises
the actual middleware and managed route, including the 500 response for a text
failure and the successful-body/JSON/empty bypasses. The native managed router
replays all 41 cases; the actual HTTP validation test exercises all 21 response
cases. Provider replay covers all 90 observations and exact diagnostic messages.

The shared persisted lifecycle contract adds an ordinal scenario: text on
suspend and failure-status JSON on reinstate retain the published errors;
successful JSON on revoke clears both persisted error fields. Existing
assertions also cover canonical status, counters, unrelated metadata, tenant
secret usage, publication ordering and late delivery-save failure. The added
25th configured image test is required by the CI runner. This composes published
provider observations with native persistence, not a new full published
lifecycle trace.

This qualifies the frozen image's default interpreter configuration, not
arbitrary changes to Python's integer-conversion setting or every remaining
transport/worker behavior.

## UTF-7: diagnostic evidence only; native implementation still pending

`canvas-utf7-boundary-oracle.json` is generated by
`scripts/canvas_utf7_boundary_oracle.py`. Its 39 cases record decoded text,
the exact published excerpt, and separate Starlette JSON rendering. Fourteen
rendering observations raise `UnicodeEncodeError`.

Strings are represented as `python_codepoints` arrays so lone surrogate values
are preserved in language-neutral JSON. Those values are not Rust Unicode
scalars. No replacement-character conversion or runtime Python shim is added.

The captures demonstrate that decoding can succeed with a lone surrogate while
later JSON rendering fails. If the surrogate lies beyond the excerpt's first
1,000 codepoints, truncation removes it and rendering succeeds. Rejecting text
at decode time would therefore change observable behavior. A lossless internal
representation, correct truncation, and consumer-specific serialization/error
handling are required before UTF-7 adoption.

This diagnostic is not a native UTF-7 parity gate and is not wired into the
general timeout runner. It requires the installed published adapter and
Starlette; the lighter local TLS environment is not assumed to provide them.
Full managed-application and provider lifecycle behavior, strict encoded-label
handling and broader UTF-7 malformed/incremental inputs remain unqualified.

## Reproduction

Run either capture script with `python /verification/scripts/<script>.py` in
the image above, mounting that script and
`scripts/run_canvas_timeout_consumer_oracle.py` as read-only siblings. Use an
isolated disposable container with no network, read-only root filesystem,
dropped capabilities and no-new-privileges. No application credentials are
needed. The ordinal script also accepts verified frozen source through its
`observe(response_source)` API for the existing helper/TLS harness.

The native ordinal regression is
`canvas_response_text::tests::continuation_ordinal_limits_match_published_parameter_and_consumer_behavior`.
The published regeneration gate is
`timeout_consumer_matches_published_socket_behavior` with
`MARTY_CANVAS_PUBLISHED_SCHEMA_TEST=1`; leaving that variable unset does not
qualify the image comparison. The native socket gate uses
`scripts/run_canvas_timeout_consumer_oracle.py --native-executable <test-binary>`.
