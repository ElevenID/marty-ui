# Published GB18030 behavior

`canvas-gb18030-codec.json` is generated by
`scripts/canvas_gb18030_codec_oracle.py` using fresh HTTPX replacement decoders
and independent Python strict decoding. It is not generated from the Rust
implementation or by replaying its mapping ranges.

Two independent captures agreed before native implementation. Both ran with
network disabled, read-only mounts/root filesystem, dropped capabilities and
no-new-privileges in the immutable published image:

`ghcr.io/elevenid/marty-credentials-issuance@sha256:9f15b64bc0ec7a693339cada3142b2952a575d2b50ee89230aabe078d0026176`

That image reports CPython 3.12.13 and HTTPX 0.26.0. The corresponding upstream
[CPython decoder source](https://github.com/python/cpython/blob/v3.12.13/Modules/cjkcodecs/_codecs_cn.c)
was inspected for byte-consumption rules (raw source SHA-256
`8b28def11821d71acb90ef3e74d7d6d597246daf4c196415107d19ebeeb73e55`).
Mappings and expected output hashes come from the image, not assumptions about
WHATWG GB18030 behavior or a newer standard revision.

## Format and coverage

Schema `marty.canvas-gb18030-codec/v1` contains:

- `pairs_zlib_base64`: zlib-compressed little-endian u32 values for every pair
  whose first byte is 128..255, indexed by `(first - 128) * 256 + second`.
  `0xffffffff` means invalid; Unicode noncharacters such as U+FFFF remain valid.
- `ranges`: 207 `[start_pointer, end_exclusive, initial_scalar]` triples mapping
  every valid four-byte pointer. Gaps are invalid. Pointer order is
  `(first - 0x81) * 12600 + (second - 0x30) * 1260 +
  (third - 0x81) * 10 + fourth - 0x30`.
- `short_hashes`: independent replacement/strict observations of each first byte
  followed by every two-byte combination, 65,792 complete inputs per mode.
- `pointer_hashes`: all 1,587,600 four-byte pointers, valid and invalid, per mode.
- `grid_hashes`: 88,741 complete inputs per mode, widths zero through four over
  the recorded 17 byte-class representatives, in lexicographic product order.
- `cases`: 428 full HTTPX response examples, including every mapping boundary,
  malformed/truncated input, mixed text and supplementary scalars. Both recorded
  canonical/alias labels are checked for every example.

Hash framing is shared with `canvas_multibyte_codec_oracle.py`: invalid strict
decode records byte 0; text records byte 1, its UTF-8 byte length as u32LE, then
the UTF-8 bytes. Each input uses fresh decoders. Rust replays the exact input
order and framing, not a digest computed from its own mapping table.

## Native owner and consumer gate

`canvas_response_gb18030.rs` uses these compact mappings and one complete-input
loop shared by replacement response decoding and strict parameter-label decoding.
Its lazy initializer validates lengths, scalar bounds and disjoint ordered ranges.
CPython checks input availability before validating byte classes: incomplete
final input becomes one replacement; a complete invalid sequence consumes only
its first byte before retrying. Strict decoding fails instead of replacing.

The mandatory published-image/schema gate regenerates and compares the entire
artifact. The actual HTTP/response-helper TLS corpus adds one mixed GB18030 case
with BMP/supplementary characters and malformed/truncated bytes, preserving all
83 previous observations. The native executable replays the same 84 cases.
Only the test fixture's exact path allowlist changes; deployment and production
transport policy do not. This qualifies GB18030, not remaining codec families
or whole-worker/all-consumer adoption.
