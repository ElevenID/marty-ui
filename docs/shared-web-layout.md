# General web header and auth layout

`ui/src/shared/web-layout/header.mjs` owns the header structure and the default
brand, **ElevenID LLC**. Its `createHeader` function accepts an element factory,
the deployment brand/logo/color, and existing action children. It has no React,
Keycloak, Supabase, routing or provider dependency. `header.css` owns only the
namespaced header styles. Page/form styling stays separate.

The application `AppHeader` component supplies `React.createElement` and keeps
the existing account/navigation actions in `AppShell`. The authenticated
`ConsoleHeaderBar` also uses that factory, supplying its existing
brand/home and mobile mode controls through optional `brandContent`/`center`
slots while keeping fixed positioning and drawer spacing in the console.
The standalone
`ElevenID/website` repository consumes an exact snapshot of `header.mjs`,
`header.css`, `verify-source.mjs` and `source.json` at the identical path, with
the same thin React adapter. Its build verifies the content-addressed source
receipt before compiling. The website adaptation record identifies the source
owner and exact revision; record the protected canonical commit there when
importing a new snapshot. No build fetches mutable remote source or requires
a package publication.

`html.mjs` adapts the same factory to escaped static HTML. Repository-owned
action/content slots remain explicit trusted markup. Runtime brand text is
always escaped; the static adapter emits no inline styles. `auth-page.css`
supplies the auth page layout without adding global resets to the React sites.

## Updating the source

From the repository root, after editing the canonical files:

```sh
node scripts/sync-web-layout.mjs
node scripts/sync-web-layout.mjs --check
```

The command regenerates the source receipt and the existing Keycloak
`auth-layout.ftl`/`resources/css/auth-layout.css`, including their Helm copies.
Keycloak continues to fill the FreeMarker action/content slots. Supabase's
static builder uses the same general HTML adapter, validates the generated
Keycloak artifacts, and includes the same combined stylesheet. Its first HTML
response and later JavaScript both use the reviewed `config.brand` value.
The public examples use `ElevenID LLC`; update the actual deployment's public
configuration too when replacing an older `ElevenID` label.

Import a reviewed source snapshot and receipt together into the website, then
update its `contracts/shared-web-header-adaptation.json` source revision and
per-file adaptation hashes. Preserve earlier extraction records. Shared-source
changes must qualify both repositories before publishing their new artifacts.

## Regression coverage

- The companion's Bun suite checks the generic source receipt, static escaping,
  Keycloak/Helm generated bytes, CSS packaging and brand/title across config modes.
- The existing application public-entry test exercises its real React header
  while retaining the navigation tests and selected test-case count.
- The website checks snapshot/provenance integrity before builds and exercises
  the real React adapter with default/custom branding and existing actions.
- `tests/test_shared_auth_layout.py` runs isolated browser checks of the actual
  general HTML adapter, auth styles and view modules at mobile/desktop widths.
  It checks keyboard focus, distinct non-submit help actions, busy controls and
  identical recovery guidance for all addresses; it makes no provider requests.
- The application source export map includes every shared source and React
  adapter, and export/restore tests verify their bytes survive packaging.

```sh
cd integrations/supabase-auth-ui
bun install --frozen-lockfile --ignore-scripts
bun test
bun build.mjs --config public/config.lifecycle.example.json
# From the repository root with the installed Playwright Chromium:
python3 -m pytest -q tests/test_shared_auth_layout.py
```

These source checks do not establish SMTP delivery, live authentication, or
the behavior of a deployed artifact. Those require the separate hosted checks.
