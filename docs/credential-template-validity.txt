Credential template validity: native runtime contract

Durations are stored as whole days, not precise seconds. Supply either day
fields or seconds aliases. ttl_seconds overrides default_validity_days;
max_validity_seconds overrides max_validity_days; reissue_within_seconds
overrides renewal_window_days. Non-null seconds aliases round up: 1, 3600,
86399 and 86400 become one day; 86401 becomes two days. Values saturate at
2147483647 days. ttl_seconds zero/negative is rejected. Released legacy
maximum/renewal seconds aliases clamp zero/negative to one day. Explicit day
fields retain their signed i32 values; renewal_window_days=0 stays zero.
Do not depend on this legacy clamping to validate intended lifetimes.

not_before_offset_seconds overrides not_before_offset and retains signed i32
seconds without day rounding. Omitted/null input fields retain stored values
on PATCH, or use native defaults on create: 365 default days, 1095 maximum
days, renewable=true, 30 renewal days, offset=0, require_revalidation=false.
revalidation_interval_days is optional and inherits when omitted/null.
Integer values outside Rust i64 seconds / i32 day-or-offset ranges fail
request deserialization. Fractions are not valid integer inputs.

Public GET/list responses return default_validity_days, max_validity_days,
renewable, renewal_window_days, not_before_offset_seconds,
require_revalidation and revalidation_interval_days, including zero/false/null.
For existing HTTP consumers, ttl_seconds and nonzero reissue_within_seconds
are also returned, computed from stored days. They do not preserve the
original seconds input. The UI uses canonical days when present and adds
convenience seconds aliases to its local model;
raw API responses are authoritative. For example ttl_seconds=86401 yields
public default_validity_days=2. A later name-only PATCH preserves that value.
The create/PATCH adapters forward supplied validity fields without creation
defaults or day conversion so native precedence and validation apply equally.
The browser update helper validates organization_id and sends it as query
transport scope. Its JSON body contains only native update fields; the native
update DTO does not accept organization_id. Stored object ownership remains
authoritative for authorization; a selector cannot reassign a template.

The gateway OpenAPI runtime extension describes these native semantics,
with separate response and runtime__credential_template_validity_input
schemas. Create/PATCH operations document that field without claiming their
other service-owned request fields are fully reconciled.
The pinned upstream protocol bundle remains unchanged. Extreme supported
storage values do not imply downstream issuance/date libraries can represent
all such timestamps; release qualification must cover intended lifetimes.
