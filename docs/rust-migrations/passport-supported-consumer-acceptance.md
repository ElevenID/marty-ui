# Supported passport consumer acceptance

The supported passport owner is Rust Gateway, Flow, and native issuance. The disposable acceptance model uses Marty’s synthetic bureau, a KMS callback signer, Signing Keys, PostgreSQL, Redis, and OpenBao. It does not start a Python issuance service or accept a Python owner phase. The simulator is selected by the `passport-beta-bureau` profile ID; no external provider or CA is required. Production configuration and resources remain unchanged.

The read-only model check in `scripts/check_passport_supported_rust_model.py` renders `docker-compose.passport-supported-disposable.yml` with the base or selfhost overlay. It requires isolated project networks and volumes, project-scoped file secrets, immutable reviewed images, a loopback HTTPS edge, and fixed Rust service roles. The protected plan binds the official `marty-ui` services and migrations OCI digests, source commit, owner labels, and a short lease. It no longer pins or attests a legacy Python image. Gateway and Flow share the Rust `issuance-native` target; the validator rejects an extra Python issuance container or an endpoint to it.

The selfhost certificate overlay temporarily enables the governed CSCA and DSC setup on Gateway and Signing Keys. Its exact delta is checked against the normal selfhost model. The certificate rehearsal verifies the KMS-backed chain, binds public certificate evidence to the current project and issuer DID, and requires plan-bound teardown. It does not prove the public Gateway operator ceremony, nine-route lifecycle, signed Gateway callback, Flow execution, or beta acceptance. A final selfhost runtime must replace the temporary ceremony containers and prove their new identities.

`scripts/check_passport_supported_compose_ownership.py` checks a running disposable project against its protected plan and record. Every container, network, and volume must have the recorded ID and matching owner labels; images, mounts, network membership, loopback port, lease, and service set are verified before a resource can be touched. Partial teardown rechecks the plan and exact live IDs, rejects unknown resources, then proves their absence. The OpenBao bootstrap, certificate helper, and bureau poll helper have fixed names and bounded network and mount rules so interrupted work can be recovered without broad Compose deletion.

The protected infrastructure and certificate rehearsal workflows exercise only their stated subsets. The protected producer joins those steps in one disposable run: it checks the attested plan and exact job budget, starts the isolated stack, issues a project-scoped Organization API key, checks live ownership, exercises the synthetic nine-route lifecycle, and proves teardown. Its hosted follow-up attests a blocked partial receipt after verifying plan lineage. The disposable model selects the exact private Rust Gateway callback URL. The producer checks the running bureau, Gateway, and native selectors, rejects proxy and custom DNS paths, binds the `gateway` Docker alias uniquely to the owned Gateway, and observes a same-job signed receipt plus native status. It advances all nine Flow steps, recreates the owned Flow and native issuance containers after the persisted SOD step, verifies that both have new container identities with the same released images, rereads the same Flow and native job checkpoint, and resumes through activation and durable history. These claims require a successful live protected run; the code and unit tests alone do not establish them. The supported-consumer collector remains blocked pending live protected route evidence for all three surfaces. The disposable selfhost runtime uses beta mode for native issuance because the Marty simulator is beta-only; that is a simulator boundary, not an external provider requirement. Kubernetes has a static simulator and callback-signer component, but still needs protected cluster identity and a complete isolated runtime.

The Kubernetes component at `k8s/passport-supported-disposable/01-simulator.yaml` defines namespace-scoped Marty simulator and callback-signer services. The read-only preflight binds the exact disposable context, cluster TLS authority, namespace, source/run labels, immutable ConfigMap, Deployment and Service UIDs, and the callback signer NetworkPolicy to a protected plan. The collector then binds Deployment, ReplicaSet, Pod, and controller-managed EndpointSlice identities; it requires the expected Rust selectors, private simulator URLs, and ready endpoints, and rejects host networking, host ports, host aliases, custom DNS, proxy routing, and external Service IPs. It repeats the identity preflight after runtime observation. This component does not provision a complete cluster or establish protected ownership by itself.

The protected Flow gate is frozen in `contracts/passport-supported-flow-acceptance.json`. The direct route probe uses placeholder application template, credential template, and delivery destination IDs and a caller supplied synthetic Flow ID. The separate Flow producer provisions tenant-bound references in the owned disposable project, starts a real physical-document Flow, advances its nine steps, and checks the durable instance, native job, managed signer, same-job signed Gateway callback, and restart checkpoint. After the restart it submits that selected job in a two-job native batch through the public Gateway, proves the first accepted SOD/DSC material in the exact owned PostgreSQL container, and binds the final native container and issued DSC to the protected receipt. Private pending batch state remains until verified disposable teardown. A successful protected run and attested receipt are still required as live evidence. A capability response or copied Flow ID cannot satisfy that gate.

Before removing migrated Python passport code, the team must review the Rust parity tests and packaged image, run the protected acceptance evidence, and find every remaining consumer of the migrated Python path. Failed gates block deletion. After those gates pass, delete the superseded Python passport routes and runtime wiring, deploy one aggregate Rust-only release to beta, record the demo and soak, and leave production unchanged. The optional reusable integration/compliance fixture remains later work.
