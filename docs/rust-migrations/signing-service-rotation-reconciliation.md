# Signing service Transit rotation reconciliation

An uncertain Transit rotation leaves a durable Redis marker scoped to the tenant and KMS endpoint, mount, namespace, and key reference, plus a service-level lookup index. Pending registry state, marker, and index are written atomically. Service replacement or rebinding does not remove them. The public rotation route returns 409 for that identity until reconciliation completes. Do not edit the marker or registry directly in Redis.

1. Quiesce rotation requests for the affected tenant and KMS key. Record the incident, tenant, service, operation ID, baseline version, and time from authenticated `GET /internal/registry/{organization_id}/services/{service_id}/rotation-reconcile`. Its `operations` list remains available after a service rebind or removal and may contain more than one unresolved key identity. Keep the corresponding OpenBao audit records. If the service was rebound, restore the affected operation's original registered KMS identity only when it is safe to inspect or reconcile that key.
2. Wait at least 30 seconds after the recorded start time and confirm the original request and worker have ended. Authenticated `POST` to the same path with `{"operation_id":"..."}` holds the tenant registry lease and reads the live Transit version twice. It accepts only a stable version exactly one greater than the recorded baseline and a matching service and operation. It then writes the previous-version overlap and rotation metadata, and clears the marker with an owner-fenced operation.
3. A successful response requires renewed certificate material and verification of the current KMS public key before JWKS and DID publication. Record the new version and publication checks in the incident. The reconciliation response does not claim that publication occurred.
4. If the version is unchanged, jumped, unreadable, or unstable, the key remains blocked. Review OpenBao audit evidence and retain the incident record. The safe operational recovery in this wave is to provision a new KMS key, rebind the issuer profile through its normal gated path, renew certificate material, and leave the unresolved old key blocked. Do not infer from an unchanged version alone that a timed-out POST never committed. Reuse of the old key requires a separately reviewed audited repair; this route cannot clear an unchanged marker.

The route uses the existing internal signing API key and accepts no caller-supplied KMS locator or private key material. The public rotation route continues to use only its tenant-registered service and key reference.
